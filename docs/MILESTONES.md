# Milestone implementation and acceptance

All eight phases have an executable reference path or supporting interface in the bounded local demonstration. This does **not** mean all research architecture milestones have met their original scientific acceptance criteria.

| Phase | Implemented software | Validation | Remaining acceptance |
|---|---|---|---|
| I: Knowledge | Strict source ingestion, ontology vocabulary, claims, typed links, fingerprints, event history | Ingestion, restart, rollback and source integrity tests | Literature retrieval, full ontology, source credibility and experimental datasets |
| II: TGA-Ω | Dependency snapshots, paths, SCC cycle groups, isolates, contradiction prompts | Graph and CLI integration tests | Validated state-space topology, weighted/explanatory gap metric and transition analysis |
| III: Theory factory | Bounded rational-polynomial candidates with assumptions, models, falsifiers and IDs | Factory bounds, exact predictions and canonicalization | General physics models, symbolic backends and specialist agent generation |
| IV: Verification | Q[x] coefficient certificates, alternate evaluator, sample criticism, counterfactuals, rejection | Exact identities, counterexamples, retained rejection history | General proof systems, quantum/GR constraints, independently controlled verification |
| V: Planner | Budget-aware action selection, finite workflow policy, persisted scores and decisions | Ranking, ties, invalid estimates, exhausted budgets | Calibrated scientific utility and open-ended adaptive research planning |
| VI: Benchmark | Train/holdout separation, persisted ranking before scoring, failed-baseline retention | Known bad baseline fails and a candidate passes finite samples | External withheld problems, leakage audit, independent adjudication and Ω3 acceptance |
| VII: Experiment | Uniform-prior outcome entropy, cost-bounded distinguishing proposals, pending-human-review state | Information-gain, affordability and no-execution tests | Human scientific approval, practical design, lab integration and actual measurements |
| VIII: Demonstration | One-command local run, complete artifacts, failure recovery, manifest verification and CI | End-to-end run, deterministic report, corruption detection | Genuine open problem, new physical prediction, independent replication and publication |

The bundled task is a synthetic software demonstration. It intentionally retains a failed pre-holdout champion and makes no discovery claim. Scientific acceptance remains pending where the table says so; it requires evidence and work beyond code completion.
